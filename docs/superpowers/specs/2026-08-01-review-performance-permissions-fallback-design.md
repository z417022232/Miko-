# 待确认、性能、权限与班次窗口兜底设计

## 目标

在不删除历史工时、工资、轨迹和人工修改的前提下，完成以下改进：

1. 统计页的待确认记录可以进入详情、修正并确认。
2. 减少定位后台处理和 Compose 页面重组造成的卡顿。
3. 权限页可直接跳到每项对应设置，并提供“修复下一项”。
4. 用户设置的上下班时间同时定义白班窗口及其反向夜班窗口；缺失通勤轨迹时按最近且已经结束的班次窗口补全，并进入待确认。

## 待确认流程

- 统计页“待确认”指标可点击，打开当月待确认列表。
- 每条待确认记录可打开确认详情。
- 详情允许修改班次、到岗时间、离岗时间、计入工时和备注。
- 用户点击“确认”后，记录清除 `needsReview`、标记为人工确认，并写入人工覆盖审计记录。
- 自动定位不得再覆盖已确认的人工结果。
- 确认前必须校验离岗晚于到岗；跨午夜夜班允许离岗属于次日。

## 班次窗口与缺失轨迹兜底

- 设置中的 `workStartMinutes` 和 `workEndMinutes` 定义白班开始与结束。
- 夜班自动使用反向窗口：白班为当天 `start → end`，夜班为当天 `end → 次日 start`。
- 示例：设置 09:00–21:00，则白班为当天 09:00–21:00，夜班为当天 21:00–次日 09:00。
- 当应用获得可靠的公司内定位、但缺少“离家→到公司”轨迹时，使用距离检测时刻最近的班次窗口作为候选。
- 候选窗口尚未结束时只建立待确认草稿，不生成未来离岗时间。
- 候选窗口结束后，如果到岗或离岗缺失，则用候选窗口相应边界补齐。
- 如果两端均缺失，则补成完整班次窗口。
- 可靠定位事件优先于窗口边界；只补缺失端，不覆盖已有可靠时间。
- 手动或已人工确认记录优先级最高，不参与自动覆盖。
- 所有使用窗口补全的记录都标记为待确认，并注明“按设置班次窗口补全”。

## 权限跳转

- 页面顶部提供“修复下一项”，按以下顺序定位第一个缺失项：精确定位、后台定位、通知、电池不受限制、Vivo 自启动。
- 每一项权限行也可单独点击。
- 精确定位、后台定位和通知使用 Android 支持的运行时申请或应用权限页面。
- 电池限制进入本应用的电池优化豁免页面；不可直达时进入系统电池优化列表。
- Vivo 自启动按已知 OriginOS 组件依次尝试；均不可用时回退到应用详情，并显示手动路径说明。
- 返回应用时重新检测所有可检测状态。
- 系统不允许应用代替用户切换权限，因此“一键”定义为直达正确设置页面，而非自动授权。

## 性能设计

### 后台定位

- 定位回调通过单一串行队列处理，防止 GPS 与网络回调并发读写数据库。
- 用户设置缓存在服务内，仅在设置变化时更新。
- 最近 14 个有效班次的学习结果缓存，在相关工时记录变化后失效，不在每次定位回调中重新查询和计算。
- 一次定位的状态、轨迹和必要记录在同一处理流程中完成。
- 运行日志只记录状态变化、异常、候选边界和确认事件；不再为每个未变化的定位写普通日志。
- 保留经过精度、时间和提供器去重后的必要定位轨迹，不以性能优化为由删除用户历史数据。

### 页面与数据流

- 月份记录建立日期索引，避免为每个日历日期遍历整月列表。
- 月份变化才切换 Room `Flow`；保存记录后依靠现有 Flow 自动刷新，不重复取消和重建监听。
- 统计汇总和每周数据基于当前记录列表使用稳定缓存。
- 每日明细以日期作为稳定键，降低无关重组。
- 待确认列表只读取当月确认项，不扫描原始定位日志。

## 错误处理

- 无法解析或不合时序的人工时间不允许确认，并显示具体原因。
- 系统设置页面不可用时安全回退，不导致应用崩溃。
- 未取得定位权限时不启动新的定位监听，权限恢复后由现有恢复机制重启。
- 窗口兜底无法唯一判断班次时选择时间距离最近者，并保持待确认状态。

## 数据与兼容性

- 优先复用现有字段；若审计信息需要新增字段，使用可回滚的 Room 迁移。
- 不删除或改写工资记录、人工记录和已有可靠时间。
- 使用现有包名、签名及前台服务通知覆盖安装。
- 不增加首页后台状态卡，不修改或停止 FlClash。

## 测试与验收

- 待确认记录可以进入详情，修改后确认并立即从待确认列表消失。
- 确认拒绝离岗早于到岗，允许跨日夜班。
- 09:00–21:00 正确生成白班 09:00–21:00 和夜班 21:00–次日 09:00。
- 无轨迹且在公司时选择最近班次窗口；窗口未结束不写未来离岗。
- 窗口结束后补齐缺失的一端或两端，并保持待确认。
- 可靠事件和人工记录不被兜底覆盖。
- “修复下一项”按固定优先级选择缺失权限；各权限行选择正确系统 Intent，Vivo 失败可回退。
- 并发定位按顺序处理；设置和学习结果不会每次定位重复查询。
- 月份监听不会因普通保存重复启动；统计计算只在输入记录变化时更新。
- 全量单元测试、Lint 和 Debug 构建通过。
- 同签名覆盖安装后，历史工时、工资、设置和包名保持不变，前台定位服务正常运行。
