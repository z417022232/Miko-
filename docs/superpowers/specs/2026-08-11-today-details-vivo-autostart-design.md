# 当天导航、每日明细与 Vivo 自启动状态修复设计

## 目标

修复以下三个问题，同时保留现有工时、工资、定位、设置、签名和后台服务行为：

1. 应用从后台重新进入前台时自动回到当天。
2. 统计页所有每日明细都可点击查看或修改。
3. Vivo 自启动不再固定显示“去设置”，并在重启后实际验证后台记录服务已自动恢复。

## 应用回到当天

- 首次打开应用时，记录月份和选中日期设为系统当天。
- 应用真正离开前台后再次进入前台时调用同一“回到今天”动作。
- 仅在应用前后台状态变化时重置；应用内部切换记录、统计、设置页不重复重置。
- 用户停留应用内查看历史月份时不被定时器或定位回调打断。
- 从系统权限页返回也属于重新进入前台，因此回到当天。

## 每日明细点击与编辑

- 统计页“每日明细”的所有工作记录都提供点击反馈。
- `needsReview = true` 的记录打开“修改并确认”编辑器。
- 普通或已确认记录打开相同字段的“编辑记录”编辑器。
- 编辑字段包括白班/夜班、到岗时间、离岗时间、计入工时和备注。
- 保存普通记录后标记为人工记录并写人工覆盖审计，自动定位不得覆盖。
- 确认待确认记录后清除待确认标记，并写人工覆盖审计。
- 离岗时间必须晚于到岗时间；夜班允许离岗属于次日。
- 待确认统计卡及其待确认列表入口继续保留。

## Vivo 自启动状态模型

采用三态状态：

- `UNKNOWN`：尚未由用户确认，显示“去设置”。
- `USER_CONFIRMED`：用户从 Vivo 自启动设置返回并确认开关已开启，显示“已开启”。
- `BOOT_VERIFIED`：设备开机/用户解锁后，广播接收器成功请求恢复后台记录服务，显示“已验证”。

状态保存在应用私有 SharedPreferences 中，不需要 Room 数据库迁移。覆盖安装保留该状态，卸载会按 Android 规则清除。

### 设置交互

- 点击 Vivo 自启动行继续打开 OriginOS/iManager 自启动管理。
- 返回应用后显示一次确认对话框：“是否已开启工时记录助手自启动？”
- 用户确认后写入 `USER_CONFIRMED`；取消则保持原状态。
- 已开启或已验证时仍可点击该行重新检查设置。
- Vivo 未提供普通应用可稳定调用的公开开关读取 API，因此不读取私有数据库或隐藏接口。

## 重启后自动恢复

“自动启动应用”定义为自动启动后台记录能力，不强制弹出主界面：

- 设备开机、用户解锁和应用覆盖升级时由现有恢复入口请求启动前台定位服务。
- 同时重新安排 15 分钟健康检查，并确保围栏恢复注册。
- 恢复请求成功后记录 `BOOT_VERIFIED`；服务启动失败时保留 `USER_CONFIRMED`，写入诊断日志并等待健康检查重试。
- 通知栏显示 Android 要求的常驻前台服务通知。
- 用户主动“强行停止”应用后，Android 禁止广播自动恢复；用户必须重新打开应用一次。

## 架构边界

- `AppForegroundTracker`：把 Activity/进程前后台事件转换为一次 `vm.today()` 调用。
- `RecordEditAction`：根据 `needsReview` 决定标题和保存语义；共享现有确认编辑器。
- `AutostartVerificationStore`：读写自启动三态，不依赖 Compose 或 Vivo 私有 API。
- `BootReceiver`/`ServiceRecovery`：在恢复路径成功后写入开机验证状态。
- `PermissionSettingsPage`：显示状态、发起设置跳转及返回确认，不直接实现状态持久化。

## 数据与并发保护

- 不删除、不重建、不批量修改任何历史记录。
- 不覆盖人工记录或可靠定位时间。
- 不增加 Room schema 版本。
- 保留当前工作区已有的后台恢复和围栏修改，实施时先隔离并基于其完整内容继续。
- 不停止、关闭或配置 FlClash。

## 测试与验收

- 首次进入应用时月份和选中日期为当天。
- 浏览历史月份后，应用离开前台再打开会回到当天。
- 应用内部切换页面不会重置正在查看的历史月份。
- 每日明细中的待确认记录可打开确认编辑器。
- 每日明细中的普通记录可打开编辑器，保存后成为人工记录。
- 自启动状态从 `UNKNOWN → USER_CONFIRMED → BOOT_VERIFIED` 正确变化并持久化。
- 取消返回确认不会错误标记已开启。
- BootReceiver 恢复成功才写入 `BOOT_VERIFIED`，失败不升级状态。
- 权限页正确显示“去设置”“已开启”“已验证”。
- 全量单元测试、Lint 和 Debug 构建通过。
- 使用现有同一签名覆盖安装；安装前后核对工时、工资、设置和数据库版本不变。
- 真机验证打开应用自动到当天、两类每日明细均可点击、Vivo 状态确认流程和后台服务通知。
- 安装完成后等待用户确认；仅在用户明确确认完成后推送 GitHub 并合并分支。
