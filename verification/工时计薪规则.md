> 来源：2026-09-12 与用户逐条确认边界后整理。
> 当前状态：**已产品化**（A1=finalize 自动算 finalMinutes @33d830c；A2=needsReview 结构化原因 @02eaa1a）。

## 0. 名词定义

| 术语 | 定义 |
|------|------|
| `上班时间` | WorkRecord.startTime（状态机 NEAR_COMPANY 锚点） |
| `下班时间` | WorkRecord.endTime（状态机 FINISHED 锚点，即离岗时间） |
| `离岗时间` | 同下班时间（语义别名） |
| `到家时间` | WorkRecord.homeArrivalTime（状态机 REST 锚点 + backfill 兜底） |
| `actualMinutes` | 状态机直接算出的原始分钟数 = (endTime − startTime) / 60000 |
| `finalMinutes` | 公司业务规则下的计薪分钟数（可手动覆盖） |
| `RecordStatus` | WORK / ARRIVAL_EXCEPTION / EARLY_LEAVE / REST |

## 1. 正常白班规则（基线）

| 字段 | 规则 | 公式 |
|------|------|------|
| 上班取整 | 向上取整到整点 | `上班钟点 = ⌈上班时间 / 1h⌉ × 1h` |
| 下班取整 | 向下取整到整点 | `下班钟点 = ⌊下班时间 / 1h⌋ × 1h` |
| 午休扣除 | 1h（中午 30min + 下午 30min 分散吃饭） | `扣 = 60min` |
| 加班计 | 超过 21:00 每多 1h 多算 1h | `加班 = max(0, ⌊(下班时间 − 21:00) / 1h⌋ × 60min)` |
| 取整 | 按小时向下取整 | `final = floor((工时 + 加班) / 60min) × 60min` |

**示例**：
- 准点 9:00 → 21:00：`floor((12h − 1h) / 1h) × 1h` = **11h = 660min**
- 迟到 09:49 → 21:00：`⌈09:49⌉=10:00`，`floor((11h − 1h) / 1h) × 1h` = **10h = 600min**

## 2. 边界规则（v1 全部确认）

### R1 — 迟到 ≤ 3 min 不计迟到
- 阈值：`(startTime − 09:00) ≤ 3min`
- 行为：起算时间仍按 9:00，**不触发 ARRIVAL_EXCEPTION**，status=WORK，needsReview=0。
- 理由：避免打卡机秒级误差造成全员标记迟到。

### R2 — 离岗 21:00 整（±3 min 容差）= 正常下班
- 阈值：`|endTime − 21:00| ≤ 3min`（21:00 整及 21:00–21:03）
- 行为：`effective_end = 21:00`，status=WORK，needsReview=0
- 实现：`lateMin ≤ 3 → R2`
- 理由：与 R1 迟到容差对称，避免打卡机秒级误差把 21:01 判成灰区。

### R3 — 离岗 21:04–21:29 灰色区
- 阈值：`21:03 < endTime ≤ 21:29:59`
- 行为：
  - `effective_end` 截到 21:00（加班不计）
  - `needsReview = 1`，`reviewReason = "R3 21:00-21:29 灰区"`
  - status 不变（保持 WORK/ARRIVAL_EXCEPTION/EARLY_LEAVE）
- 理由：可能加班半小时也可能有情况耽误，需人工确认。

### R4 — 离岗 ≥ 21:30 = 加班部分不计入
- 阈值：`endTime ≥ 21:30`
- 行为：
  - **加班部分归零**（`effective_end` 截到 21:00，工时部分照算，**不是把整天工时清零**）
  - `needsReview = 1`，`reviewReason = "R4 21:30+ 不计加班"`
  - status=ARRIVAL_EXCEPTION（如果原本不是）
- 理由：21:30 后离岗大概率是事情耽误，不算加班。
- **覆盖 R3**：21:30 起 R4 生效。

### R5 — 跨夜归属
- 阈值：endTime 与 startTime 不在同一天（00:00 跨界）
- 行为：归属 `workDate` = **实际打卡的下班日期**（按"几号打卡计入几号"原则）
- 实现：状态机写入时按 endTime 的本地日期归 workDate（已实现）。

### R6 — 晚到岗 / 晚离岗 / 晚到岗早离岗 = 同白班算法
- 阈值：startTime > 09:00 或 endTime > 21:00 但 < 21:30
- 行为：完全套用 §1 公式 + R1 容差 + R3 灰区标记
- 状态映射：
  - startTime > 09:00 → status=ARRIVAL_EXCEPTION
  - endTime < 21:00 → status=EARLY_LEAVE

### R7 — 早退（提前 ≥ 1h 离岗）
- 阈值：`endTime ≤ 20:00`（下班时间提前 ≥ 1h）
- 行为：
  - 套用 §1 公式，**直接按 actualMinutes 计算工时**（"提前 3h 自动算"原则）
  - 例：18:00 离岗、`上班 = 9:00`：`floor((9h − 1h) / 1h) × 1h` = **8h = 480min**
  - 例：18:00 离岗、`上班 = 10:00`（迟到 1h）：`floor((8h − 1h) / 1h) × 1h` = **7h = 420min**
  - status=EARLY_LEAVE
  - needsReview=1（早退属于异常，需人工确认）

### R8 — 午休扣除 1h（公司分散吃饭）
- 总扣除：60min
- 组成：中午 30min + 下午 30min（不是正式午休时段）
- 应用范围：所有白班规则统一扣除

## 4. 字段写入规则

### ManualFieldMask 位定义（work_records.manualFieldsMask，与 `data/entity/ManualField.kt` 一致）
**bit 0–6 是历史位（2026-09-06 起），不得改动；bit 7+ 为 A3 新增。**

| bit | 常量 | 类别 | 含义 |
|-----|------|------|------|
| 0 | `SHIFT` | 人工 | 手动改班次 |
| 1 | `COMPANY_ARRIVAL` | 人工 | 手动改上班时间 |
| 2 | `COMPANY_DEPARTURE` | 人工 | 手动改下班/离岗时间 |
| 3 | `HOME_DEPARTURE` | 人工 | 手动改出门时间 |
| 4 | `HOME_ARRIVAL` | 人工 | 手动改到家时间 |
| 5 | `FINAL_MINUTES` | 人工 | **用户手动**覆盖 finalMinutes |
| 6 | `NOTE` | 人工 | 手动改备注 |
| 7 | `AUTO_FINAL_MINUTES` | 自动痕迹 | v1 规则自动算出 finalMinutes（A1/A3） |
| 8 | `AUTO_NEEDS_REVIEW` | 自动痕迹 | v1 规则自动判定 needsReview（A2/A3） |
| 9 | `NEEDS_REVIEW_ACK` | 人工 | 用户已确认过复核（A6 UI 写） |

**核心区分**：
- `HUMAN_BITS`（bit 0-6 + 9）= 人工保护位 → 自动合并必须保留原值
- `AUTO_BITS`（bit 7-8）= 自动痕迹位 → **不参与保护判断**（否则自动算法把自己的结果锁死、后续无法重算）

辅助方法：`humanOnly(mask)` / `hasHumanProtection(mask)` / `hasAutoFinalMinutes(mask)` / `isNeedsReviewAcknowledged(mask)`

### reviewReason 字段（A2 新增，DB v10）
- 类型：`TEXT` nullable；null = 无需复核
- 取值示例：`"R1 迟到 49min；R3 21:00-21:29 灰区"`
- 生成：`WorkSessionEngine.buildSession` 从 status + v1RuleTrace 映射（多条用 `；` 分隔）
- `needsReview` 与 `reviewReason` 严格一致：`needsReview = reviewReason != null`

### note 字段约束
- 不允许出现公司敏感词（如工资金额、个人薪酬）
- 推荐格式：`"<公司规则要点>；<异常情况说明>；<证据来源>"`
- 例：`"公司分散吃饭扣 1h（中午30+下午30），迟到49分钟按整点10:00计 → 实际工时10h；到家21:20:20由状态机证据补写"`

## 6. 验证锚点（2026-09-12 已实测）

| 工时场景 | 上班 | 离岗 | 到家 | actualMinutes | finalMinutes | status | needsReview |
|----------|------|------|------|---------------|--------------|--------|-------------|
| 9/12 迟到早退 | 09:49 | 21:00 | 21:20 | 673 | 600 | ARRIVAL_EXCEPTION | 1 |

**9/12 修正链**：
1. 09:49 上班触发 ARRIVAL_EXCEPTION（b2fca68 状态透传）
2. backfill 在 FINISHED→REST 阶段补写 homeArrivalTime=21:20:20
3. 自动 finalMinutes=600（actualMinutes=673；状态机按 ARRIVAL_EXCEPTION 时 finalMinutes 算法 = (actualMinutes − 60) floor）
4. 用户手动确认为 600 后写 note 说明公司规则

**回溯**：若 finalize 自动按 v1 跑 9/12：
- 上班 = ⌈09:49⌉ = 10:00
- 下班 = ⌊21:00⌋ = 21:00
- 工时 = (21:00 − 10:00) − 1h = 10h
- finalMinutes = **600**（与手动结果一致 ✓）
