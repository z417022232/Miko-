# 工时记录助手

一款本地优先的 Android 工时记录应用，通过前台定位服务识别到达公司、离开公司和回家事件，并生成每日与月度工时记录。

## 主要功能

- 公司和家庭地理围栏
- 公司位置支持高精度多点校准；用户半径仅用于候选检测，校准后的稳定锚点用于确认事件
- 白班、夜班及跨日工时识别
- 低精度定位过滤与 60 分钟离岗确认
- 事件时间与确认时间分离：持续观察不会把首次离岗或首次到家时间推迟
- 动态省电采样：移动/围栏边缘 1 分钟、上下班窗口 5 分钟、普通状态 10 分钟、稳定在家或公司 30 分钟
- 显著运动触发 Movement Burst：临时切换到 1 分钟定位档并主动补充环境证据，最长持续 10 分钟，结束后回到统一采样策略
- 多源融合结果分为“已确认”“暂时维持”和“位置不确定”；弱证据和冲突结果不会直接改变工时状态
- 设置页实时显示当前定位判断、置信度、判断原因、证据来源和各来源明细
- 日历、月度统计、手动修正与数据导出；应用重新进入前台时自动回到当天
- 统计页所有“每日明细”均可点击：待确认记录进入确认编辑，普通记录进入人工修改
- 日历支持多选日期批量修正白班/夜班与计入工时
- 工资所属月份与实际发放日期分离
- Room 数据库无损迁移

所有工时、定位和工资数据默认只保存在手机本地。

## 构建

准备 JDK 17 和 Android SDK，并在项目根目录创建本机专用的 `local.properties`：

```properties
sdk.dir=C\:\\Users\\your-name\\AppData\\Local\\Android\\Sdk
```

Windows：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

macOS / Linux：

```bash
./gradlew testDebugUnitTest assembleDebug
```

调试 APK 生成在：

```text
app/build/outputs/apk/debug/app-debug.apk
```

## 权限说明

自动记录需要定位、后台定位、通知和前台服务权限。Android 会持续显示必要的前台服务通知，这是后台定位的系统要求。

为提升室内和锁屏场景下的定位可靠性，应用还会在系统版本支持时请求“附近设备”（Wi-Fi 与蓝牙扫描）和“活动识别”（显著运动）权限：前者用于识别公司和家庭附近的无线环境，后者用于在移动时唤醒低功耗扫描。Android 12 以下附近设备视为已满足，Android 10 以下活动识别视为已满足。

设置页的“修复下一项”和每个权限项可直接打开相应系统设置；Android 仍要求用户亲自确认权限开关。Vivo 自启动页面无法直达时，应用会回退到自身应用详情并显示手动操作提示。

Vivo 自启动状态分为“去设置”“已开启”和“已验证”：“已开启”表示用户从系统设置返回后已确认开关；“已验证”表示设备在开机、解锁或应用更新后确实完成了定位服务、健康检查和地理围栏恢复。自启动只恢复后台记录服务，不会自动弹出应用界面。用户主动“强行停止”应用后，仍需手动打开应用一次，这是 Android 的系统限制。

定位服务心跳、定位回调和可靠定位分别记录。单条异常定位会回滚并留下待确认信息，不再结束整个前台服务；定位提供器被系统关闭时会与服务退出分开提示。每个证据来源（卫星定位、运动传感器、Wi-Fi、蓝牙、基站）的健康状态分别记录，辅助来源失效只降级环境证据，不会被误报为定位服务故障。

## 唤醒与后台恢复机制

应用以持续运行的前台定位服务为主链路，并使用多层恢复机制降低系统休眠或进程回收造成的记录中断：

- 前台服务每 5 分钟更新一次心跳，并同步顺延看门狗闹钟；服务正常运行时闹钟不会触发。
- 连续错过心跳后，看门狗检查定位权限并尝试恢复前台定位服务；没有精确闹钟能力时自动退化为非精确时间窗口。
- 开机、用户解锁、应用更新和地理围栏事件分别经过权限门禁后恢复服务与围栏。
- WorkManager 定期检查服务和各证据来源健康状态，但不会直接从普通后台任务启动定位前台服务；需要用户介入时发送可点击的恢复通知。
- 显著运动传感器只负责触发重新取证，不直接声明用户位于家或公司。触发后进入最长 10 分钟的 Movement Burst；获得连续可靠判断或到达硬上限后退出，并由统一采样策略重新决定间隔。

用户主动在系统设置中“强行停止”应用后，Android 会阻止上述自动恢复链路，仍需手动打开应用一次。

## 多源定位证据与自动学习

除卫星定位外，应用会以脱敏方式采集周围的基站、Wi-Fi 和蓝牙环境特征。当用户在精度良好（50 米以内）且位置稳定（5 分钟以上）的核心区域停留时，应用自动学习“家”和“公司”的环境指纹：新指纹先处于候选状态，跨至少 3 个不同日期共 6 次观察后升级为稳定指纹，30 天未观察开始衰减，90 天未观察自动停用。

事件顺序固定为：在家 → 离家 → 到公司 → 工作中 → 离公司 → 到家。相邻可靠证据间隔超过 20 分钟视为连续性中断，中断后候选到达需要重新计数，但已确认的工作会话不会丢弃。卫星定位精度大于 100 米时不参与地点判断；环境证据单独不足时输出“未知”，不改变工时状态。

环境扫描遵循省电策略：扫描冷却至少 5 分钟，显著运动或卫星定位 20 分钟无回调时才进行一次主动短扫描，班次窗口附近只读取系统已有的扫描快照，稳定停留在已知地点时不扫描。手动记录和人工修正始终优先，不会被自动学习覆盖。

### 融合决策与状态显示

融合引擎将地点和决策等级分开处理：

- **已确认（CONFIRMED）**：可靠 GPS、网络定位或达到确认阈值的多类环境证据，可以进入工时状态机。
- **暂时维持（MAINTAINED）**：单一弱证据或短时间连续性只维持上一次判断，不触发到岗、离岗或到家转换。
- **位置不确定（UNKNOWN）**：没有数据、证据过期、家庭与公司证据冲突或置信度不足时保持安全状态，不修改工时。

设置页的“当前判断”卡片会实时显示地点、决策等级、置信度、更新时间和证据来源，并将 `UNKNOWN_NO_DATA`、`UNKNOWN_STALE`、`UNKNOWN_CONFLICT`、`UNKNOWN_LOW_CONFIDENCE` 等内部原因翻译成可读说明。运行日志同时保留融合结果与来源明细，用于真机测试和问题定位。当前没有单独的 `LIKELY_HOME` 或 `LIKELY_COMPANY` 状态；尚未达到确认门槛的倾向性证据统一按“暂时维持”或“位置不确定”处理。

## 当前验证阶段

现阶段功能已经进入真机场景验证。后续将重点核对在家静止、离家、通勤、到达公司、室内弱 GPS、临时离岗、下班到家、长时间息屏、系统回收、重启，以及分别关闭定位、Wi-Fi 或蓝牙时的表现。验证关注三个结果：误判、漏判和耗电。

仓库中的单元测试用于验证融合、保留、采样和恢复策略，但不能替代真实移动轨迹与不同厂商系统的长期运行测试。发现问题时建议同时记录发生时间、当时位置与移动状态、系统开关状态，以及“当前判断”和“运行日志”中的信息，以便复现和修正。

## 班次窗口兜底

用户设置的上下班时间定义白班窗口，反向时间自动定义夜班窗口。例如设置 09:00–21:00 时，白班为当天 09:00–21:00，夜班为当天 21:00–次日 09:00。

当应用可靠检测到用户在公司、但缺少从家到公司或离开公司的轨迹时，会按最接近的班次窗口补充缺失边界。窗口尚未结束时不会写入未来离岗时间；窗口结束后补全的记录始终标记为“待确认”，需要在统计页核对。可靠定位时间和人工记录不会被兜底覆盖。

## 隐私

项目不依赖账号或后端服务器。定位轨迹、工时记录、工资金额等敏感数据不应提交到 Git 仓库。

环境指纹不保存任何原始无线标识：基站编号、Wi-Fi 的 SSID/BSSID 和蓝牙地址只在与设备绑定的随机盐参与下进行单向哈希后才写入本地数据库，数据库中不存在可用于还原原始标识的字段。观察明细只保留 30 天并限制每来源最多 10,000 条，且从不离开设备。
